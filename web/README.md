# RamanTwin web

Interactive three.js front end of the RamanTwin demo. It runs fully offline: no CDN, no remote fonts.

## Develop

```bash
cd web
npm ci
npm run dev        # http://localhost:5173, proxies /api to http://127.0.0.1:8000
npm run build      # tsc --noEmit + vite build -> web/dist
npm run preview    # serves web/dist (also proxies /api)
```

`ramantwin-demo` serves `web/dist` and the API together on `http://127.0.0.1:8000`.

## Views

| Key | View | Space / arrows |
|---|---|---|
| 1 | Intro | go to The Shift |
| 2 | The Shift: 4000-point cloud morphing Raw → ORPL → Naive CNN → Robust CNN | next stage |
| 3 | Twin Lab: 3D instrument, live `/api/simulate` | next recorded scenario |
| 4 | Robustness Atlas: metric surfaces and fleet panel | next model (previous one ghosted), then naive vs robust |

Other keys: `F` fullscreen, `C` colour mode and `R` auto-rotate (Shift), `N` normal/cancer and `R` re-roll (Twin Lab),
`Esc` unpins the inspected point.

The Twin Lab checks `/api/health` at load. If the API is unreachable it switches to offline mode, replays the
recorded scenarios of `twinlab_samples.json` and probes `/api/health` every 5 s to resume live mode. A failed
`/api/simulate` call only shows a short error message. Only the sliders known to the web app are shown.
Clicking the current tab (or pressing its number) reloads the view.

## Data files

`public/data/` holds the four files of `docs/architecture.md` section 8: `shift_scene.json`,
`robustness_atlas.json`, `fleet.json`, `twinlab_samples.json`. The committed files are mock data
(`"mock": true`, flagged as "Mock data files" in the top bar) generated by:

```bash
npm run mock       # node scripts/make-mock-data.mjs
```

The Python export overwrites them with real results; the app accepts any contract-valid file.
